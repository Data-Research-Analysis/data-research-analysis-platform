# Google Ads Report Types & Schema Reference

> **Last reviewed:** 2026-10-22 against `GOOGLE_DEFAULT_SYNC_TYPES` (`backend/src/types/IGoogleAds.ts`) and `GoogleAdsDriver.getTableColumns()`.

## Overview

The connector writes each sync type into the `dra_google_ads` schema. Physical table names are generated by `TableMetadataService.generatePhysicalTableName(dataSourceId, logicalName)` and therefore look like `ds{dataSourceId}_{md5[:8]}`; the logical name below is what the UI and `dra_table_metadata` display.

```
dra_google_ads."ds42_ab12cd34"   -- logical name: insights (campaign performance)
```

Settings tables are keyed by the platform object id; insight tables are keyed by date range and dimension columns. All tables carry `synced_at` (and `customer_id` where applicable).

| 2 | `ad_groups` | Ad group settings | `id`, `name`, `campaign_id`, `campaign_name`, `status` | `cpc_bid` |
| 3 | `ads` | Ad configuration/creative text | `id`, `ad_group_id`, `campaign_id`, `ad_type`, `status` | `headlines`, `descriptions`, `final_urls`, `display_url` |
| 4 | `insights` | Campaign daily performance | `campaign_id`, `campaign_name`, `date_start`, `date_stop` | `impressions`, `clicks`, `spend`, `conversions`, `conversion_value`, `ctr`, `cpc`, `cpm`, `cpa`, impression-share fields |
| 5 | `ad_group_insights` | Ad group daily performance | `campaign_id`, `ad_group_id`, `ad_group_name`, `date_start`, `date_stop` | same metric set as `insights` |
| 6 | `demographic_insights` | Age/gender performance | `campaign_id`, `ad_group_id`, `age_range`, `gender`, dates | same metric set |
| 7 | `device_insights` | Device performance | `campaign_id`, `device`, dates | same metric set |
| 8 | `geographic_insights` | Country/region/city performance | `country_criterion_id`, `country`, `region`, `city`, dates | same metric set |

### Insight metric columns

All `*_insights` tables share the metric set defined by `getInsightMetricColumnDefs()`:

`impressions`, `clicks`, `spend`, `conversions`, `conversion_value`, `all_conversions`, `all_conversions_value`, `view_through_conversions`, `cross_device_conversions`, `search_impression_share`, `search_lost_impression_share`, `search_top_impression_share`, `search_absolute_top_impression_share`, `click_share`, `interactions`, `interaction_rate`, `ctr`, `cpc`, `cpm`, `cpa`, `cpv`, `video_views`, `video_view_rate`, `reach`, `active_view_impressions`, `active_view_ctr`, `active_view_viewability`, `invalid_click_rate`, `customer_id`, `synced_at`.

> ROAS is not stored as a column; compute it as `conversion_value / NULLIF(spend, 0)`.

## Legacy sync types

Pre-v25 configurations used `campaign`, `keyword`, `geographic`, `device`, and `ad_group`. These are normalized to the current names during sync:

| Legacy | Current |
|---|---|
| `campaign` | `insights` (campaign performance) |
| `keyword` | `keyword_insights` |
| `geographic` | `geographic_insights` |
| `device` | `device_insights` |
| `ad_group` | `ad_group_insights` |

The legacy `campaigns` performance table (detected by `date` + `campaign_id`) is dropped after the schema upgrade; the new `campaigns` table holds settings.

## Sample queries

```sql
-- Daily campaign performance with ROAS
SELECT date_start, campaign_name, spend, conversions,
       ROUND(conversion_value / NULLIF(spend, 0), 2) AS roas
FROM dra_google_ads."ds42_ab12cd34"
ORDER BY date_start DESC;

-- Spend and CPA by device
SELECT device, SUM(spend) AS spend, SUM(conversions) AS conversions,
       ROUND(SUM(spend) / NULLIF(SUM(conversions), 0), 2) AS cpa
FROM dra_google_ads."ds42_ab12cd34"
GROUP BY device
ORDER BY spend DESC;

-- Top keywords by conversions
SELECT keyword_text, match_type, quality_score,
       SUM(clicks) AS clicks, SUM(conversions) AS conversions
FROM dra_google_ads."ds42_ab12cd34"
GROUP BY keyword_text, match_type, quality_score
ORDER BY conversions DESC
LIMIT 25;
```

## Best practices

- Filter by `date_start`/`date_stop` and aggregate; insight tables are daily grain.
- Join settings tables to insight tables on `campaign_id` / `ad_group_id` (settings tables are per data source, like insight tables).
- Treat impression-share fields as fractions (0–1).
- For MCC sources, each client account has its own physical tables; use `customer_id` to distinguish clients.
